# Changes — v2.5.0 (2026-09-25)

Addresses [Issue #66](https://github.com/AndrewTapp/solaredgeoptimizers/issues/66):
portal layouts that list more than one inverter for the same logical slot
(e.g. a replaced unit left as INACTIVE with no children) were registered as
extra Home Assistant devices (`Inverter 1a`, variant ghosts). Those devices
could not be deleted because the integration did not implement device removal.

No new Python dependencies (`manifest.json` remains `requirements: []`).

## Duplicate inverter slots (option 1)

- After layout parse, `collapse_duplicate_inverter_slots()` keeps **one inverter
  per `displayName` / displayOrder**.
- Selection: sole **ACTIVE** (or blank status) peer when unambiguous; otherwise
  the row with the **most optimizers**; serial as final tie-break.
- Distinct slots (`1` and `2`) on true multi-inverter sites are unchanged.
- Optimizer / string ACTIVE+INACTIVE pairs at the same panel position are **not**
  collapsed (lifetime history for replaced panels stays as before).
- Dropped rows are logged at INFO (serial, status, optimizer count, kept serial).

## Removable devices (option 2)

- Implements `async_remove_config_entry_device` so **Delete device** works in the
  Home Assistant UI for inverter, string, and optimizer devices.
- The **site** parent device cannot be removed while the config entry exists;
  attempting Delete raises a clear `HomeAssistantError` for the dialog message.

## What to do in Home Assistant after upgrading

1. Update to **2.5.0** (HACS or copy `custom_components/solaredgeoptimizers/`).
2. Restart Home Assistant, then **reload** the SolarEdge Optimizers integration
   (or restart again after reload).
3. Confirm logs (optional): an INFO line when a duplicate inverter row is dropped.
4. Open **Settings → Devices & services → Devices**, find ghost inverters /
   strings / optimizers (unavailable / restored, no live data), open each device
   → **Delete**.
5. They should **not** reappear after the next 5-minute coordinator cycle.

If ghosts remain confusing, delete and re-add the integration (same Site ID /
credentials / options); history reconnects when `unique_id`s are unchanged.

## Real-world examples

| Site pattern | Before 2.5.0 | After 2.5.0 |
|--------------|--------------|-------------|
| Single ACTIVE inverter (most sites) | One inverter device | No change |
| Slot `1`: INACTIVE empty + ACTIVE with tree (Issue #66, neo8101-like) | `Inverter 1` + `Inverter 1a` (and variants) | Only the ACTIVE / tree row registered; ghosts deletable |
| Two real inverters `displayOrder` `1` and `2` | Both kept | Both kept |
| Replaced **optimizer** at `1.0.11` (ACTIVE + INACTIVE) | Suffixes / lifetime for both | Unchanged (not inverter-slot collapse) |

## Versioning

Minor bump **2.4.22 → 2.5.0**: user-visible behaviour change (fewer devices for
affected sites; device delete enabled) without a unique_id scheme migration.
