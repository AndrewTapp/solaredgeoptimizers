# Changes — v2.5.1 (2026-11-11)

Addresses [Issue #71](https://github.com/AndrewTapp/solaredgeoptimizers/issues/71):
empty SolarEdge One layouts crashed lifetime-energy refresh (`max_workers must be
greater than 0`), and legacy layout fallback logged confusing JSON parse errors
when SolarEdge returned HTTP 410 / an empty body for the retired
`…/solaredge-apigw/api/sites/{id}/layout/logical` endpoint.

No new Python dependencies (`manifest.json` remains `requirements: []`).

## Empty optimizer list (One + legacy)

- SolarEdge One `_fetch_lifetime_energy_uncached()` returns `{}` when the layout
  has no optimizer serials (no `ThreadPoolExecutor(max_workers=0)`).
- Legacy `requestAllData()` returns `[]` when the layout has no optimizers.

## Legacy 410 / empty-body logging

- Legacy logical-layout GET raises `SolarEdgeAPIError` on HTTP 410, non-200, or
  empty body instead of feeding empty text into `json.loads`.
- Non-JSON legacy layout responses are remapped to the same clear error (WARNING),
  not a raw `Expecting value…` ERROR.
- Dual API logs a single WARNING when legacy layout is retired/unavailable and
  points users at SolarEdge One.
- Setup login check status **410** logs that One also failed and legacy is Gone.

## What to do in Home Assistant after upgrading

1. Update to **2.5.1** (Marketplace / **Settings** → **Updates**, or copy `custom_components/solaredgeoptimizers/`).
2. Confirm **Use SolarEdge One** is **Yes**.
3. Reload the integration (or restart Home Assistant).
4. If setup still fails with 410, re-authenticate with the same portal credentials
   that work in the current monitoring UI.

## Docs: Marketplace (Home Assistant 2026.11+)

- Install/update instructions now prefer **Settings → Marketplace** (replaces HACS).
- `hacs.json` / `zip_release` packaging is unchanged; HACS steps kept only for HA ≤2026.10.

## CodeFactor polish

- Module docstring in `solaredge_one_api.py`: removed English semicolons that CodeFactor
  flagged as E702 (false-positive style noise inside the docstring).
- `api_dual.requestAllData`: extracted small helpers to bring method complexity under the
  CodeFactor “Complex Method” threshold.

Patch **2.5.0 → 2.5.1**: defensive empty-list handling, clearer legacy-gone logs, Marketplace docs, CodeFactor polish.
