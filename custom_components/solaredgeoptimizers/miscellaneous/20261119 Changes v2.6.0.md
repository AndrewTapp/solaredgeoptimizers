# Changes — v2.6.0 (2026-11-19)

Adds SolarEdge One layout support for **SMI** (Safety and Monitoring Interface)
parent sites ([Issue #74](https://github.com/AndrewTapp/solaredgeoptimizers/issues/74)).

No new Python dependencies (`manifest.json` remains `requirements: []`).

## SMI parent layout (SolarEdge One)

- Site structure parsing now walks top-level `FOLDER` / `SMI` nodes as well as
  `FOLDER` / `INVERTER`.
- Each SMI keeps the same internal parent role as an inverter:
  **Site → SMI → String → Optimizer**, with **position / `displayOrder`-based**
  device and entity identity (serial remains for API fetches and attributes only).
- Home Assistant device names use **SMI** `{site}.{n}` when the portal parent
  type is SMI; inverter sites are unchanged.
- Sibling `BATTERY` / `METER` folders remain ignored (no change; separate future work).
- `layout/information/inverters` model fetch is skipped for SMI serials (that
  endpoint expects inverter serials). Optimizer live data continues to use
  optimizer serials. Parent temperature / by-inverter lifetime still pass parent
  serials and degrade gracefully if the portal rejects SMI ids.
