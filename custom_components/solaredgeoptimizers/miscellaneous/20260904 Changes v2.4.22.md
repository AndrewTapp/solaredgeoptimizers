# Changes — v2.4.22 (2026-09-04)

Consolidated hardening since v2.4.21: quieter operational logging, safer resource
shutdown, Home Assistant device-registry compatibility, stale-value corrections,
and documentation/quality cleanup. No runtime Python dependencies are added.

## Device registry

- Migrated all Site → Inverter → String → Optimizer parent links from deprecated
  identifier-based `via_device` to registry-scoped `via_device_id`.
- Coordinator-created parents use the `DeviceEntry.id` returned by
  `async_get_or_create`; optimizer registration resolves its string parent with
  `async_get_device_id_by_identifier(..., config_entry_id=...)`.
- Missing optimizer parents degrade safely with one warning instead of failing
  setup. The existing identifiers-only entity links remain unchanged.
- Removes the three deprecation warnings emitted by Home Assistant 2026.8+ and
  remains compatible with the API required by Home Assistant 2027.8.

## Resource and file-descriptor handling

- Setup failures, unloads, and config-entry removals shut down coordinator work
  before closing both API backends.
- Legacy thread-local sessions remain tracked and close waits long enough for the
  configured longest HTTP timeout before releasing connection pools.
- SolarEdge One requests are tracked while in flight; close prevents new work,
  waits for active requests within a bounded interval, and then clears OAuth
  tokens.
- The dual API rejects calls after close, remains idempotent, and still attempts
  to close both backends if either close operation fails.
- Response and executor context managers continue to close transient responses,
  OAuth sessions, and thread pools deterministically.

## Logging

- Per-optimizer lifetime-energy HTTP 403 is WARNING once per serial and DEBUG on
  repeats.
- Device hierarchy registration is INFO once per coordinator and DEBUG on
  subsequent registration passes.
- Legacy response headers, cookies, complete payloads, raw query strings, and
  oversized response previews are no longer written to DEBUG.
- High-volume per-sensor, per-optimizer aggregation, and per-node layout logging
  is replaced by bounded summaries.
- Empty optimizer measurement diagnostics are summarized to avoid repeated
  warnings while preserving actionable detail.
- Setup, source-switch, entity-registration, authentication, cleanup, and close
  summaries remain available at appropriate levels.

## Data and compatibility fixes

- Before `_timetocheck` is initialized, stale live values now use the correct
  backend threshold: one hour for SolarEdge One and two hours for legacy.
- Legacy chart timestamps use timezone-aware
  `datetime.fromtimestamp(..., tz=timezone.utc)`.
- Removed unused constants and retained stdlib-only legacy JSON extraction
  introduced in v2.4.21 (`manifest.json` remains `requirements: []`).

## Code quality and documentation

- Removed trailing whitespace and corrected pycodestyle spacing, unused
  variables, loop closure capture, and focused device-registration complexity.
- Kept legacy camelCase API names and broad exception handling at cleanup/HA
  boundaries where compatibility or guaranteed cleanup requires them.
- The full local Pylint audit scored 9.44/10 before targeted cleanup. Remaining
  reports are mainly intentional portal-compatible camelCase names, Home
  Assistant entity shape/attribute patterns, and existing module
  complexity/duplication. These were not broadly refactored for this release.
- The extracted registration helpers reduced
  `_register_inverter_and_string_devices` from Radon C (15) to B (8). Other
  existing C-grade paths remain documented technical debt.
- Updated module headers, README, HACS info, Wiki, SolarEdge One API summary, and
  internationalization notes to reflect v2.4.22 behavior.
